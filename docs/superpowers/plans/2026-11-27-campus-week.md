# 대학생으로 일주일 살아남기 구현 계획

**목표**는 대학생의 7일을 플레이하는 한국어 웹 게임을 UTF-8 `index.html` 한 파일로 만드는 것이다.

**설계 기준**은 [BRIEF.md](../../../BRIEF.md)다. 구현 파일은 프로젝트 루트의 `index.html` 하나다. HTML에 시작·진행·엔딩 영역을 두고, 같은 파일에 CSS와 일반 JavaScript를 넣는다. JavaScript가 요일, 능력치, 화면 단계, 마지막 선택 결과를 메모리에서 관리한다.

## 작업 범위

- 파일을 더블클릭해 브라우저에서 실행한다. 서버, 설치, 외부 파일, 로그인 없이 플레이할 수 있어야 한다.
- 폭 390px에서 진행도와 능력치를 중심으로 한 열에 배치하고 가로 스크롤 없이 읽고 선택할 수 있게 한다.
- 구현과 확인에는 Git, 테스트 코드, 하위 에이전트를 사용하지 않는다. 이 문서는 구현 착수 전에 작성하며 공개 배포는 별도 요청으로 진행한다.

## 1. HTML 틀, 데이터, 시작 화면

- [ ] `index.html`에 `lang="ko"`, UTF-8 선언, 모바일 뷰포트를 설정한다. 처음 표시되는 시작 화면에는 게임 제목, 7일 동안 매일 하나를 고르는 규칙, `시작` 버튼을 둔다. 게임 화면에는 진행도, 능력치, 요일, 사건, 선택이나 결과를 표시할 영역을 둔다.
- [ ] `BRIEF.md`의 CSV 헤더와 7개 행을 JavaScript 문자열에 그대로 넣는다. 고정 형식에 맞춰 줄과 쉼표로 나누고, 헤더 다음부터 각 행을 요일, 사건, 선택 두 개로 읽는다. 각 선택은 화면에 표시할 문구와 학업·체력·행복 순서의 숫자 세 개를 가진다.
- [ ] 월요일을 첫 요일로 사용하고 학업·체력·행복을 모두 50으로 초기화한다. `시작`을 누르면 월요일 선택 화면에 `1 / 7`, 세 능력치의 막대와 숫자, 요일, 사건, CSV 순서대로 배치한 두 버튼을 표시한다. 변화량은 선택 후 공개한다.
- [ ] 브라우저에서 파일을 직접 열어 제목과 버튼을 확인한다. `시작`을 눌러 월요일의 문구와 능력치 `50 / 50 / 50`을 확인한다. 내장 CSV를 원본과 줄 단위로 대조한다.

## 2. 선택 처리와 다음 날 이동

- [ ] 화면 단계는 시작, 선택, 결과, 엔딩으로 구분한다. 선택 단계에서만 A 또는 B 버튼을 받아 처리 중인 선택을 즉시 잠근다. 기존 값을 보관하고 각 능력치에 해당 CSV 변화량을 더한 뒤 0~100으로 제한한다. 선택한 문구와 제한 후 값에서 이전 값을 뺀 실제 반영량을 기록한다.
- [ ] 엔딩 조건에 해당하지 않으면 결과 단계로 전환한다. 요일, 사건, 진행도와 능력치 영역을 같은 위치에 두고 능력치 숫자와 막대를 갱신한다. 선택 버튼 두 개를 고른 행동, 부호가 있는 실제 반영량과 적용 후 능력치, `다음 날` 버튼으로 교체한다. 반영량이 0이면 `0`으로 표시한다.
- [ ] 결과 단계에서만 `다음 날` 입력을 받는다. 요일을 한 칸 진행시키고 기존 능력치로 새 선택 화면을 그린다. 능력치 변화는 선택 버튼에서만 일어난다.
- [ ] 월요일 A를 빠르게 연속 클릭해도 능력치가 `65 / 40 / 45`, 변화량이 `+15 / -10 / -5`인 결과가 한 번만 나오는지 확인한다. `다음 날`을 누르면 화요일에 같은 능력치를 이어받고 변화량은 가려져 있어야 한다.

## 3. 엔딩과 다시 시작

- [ ] 선택 적용 직후 능력치 중 0이 있으면 즉시 **재충전 필요**를 표시한다. 0이 없고 일요일이라면 세 능력치가 모두 40 이상일 때 **균형 달인**, 하나라도 40 미만이면 **아슬아슬 생존**을 표시한다. 나머지 날에는 결과 화면으로 이어진다.
- [ ] 엔딩 화면에 엔딩 이름, 마지막 선택 문구, 실제 반영량, 최종 능력치, `다시 시작`을 표시한다. `다시 시작`은 요일, 능력치, 선택 결과를 새 게임 상태로 되돌리고 시작 화면을 연다. 다시 `시작`을 누르면 월요일에 능력치가 모두 50이어야 한다.
- [ ] 각 경로는 월요일부터 A와 B를 순서대로 누르고, 일반 결과에서는 `다음 날`을 누른다. 마지막 선택 직후 별도 클릭 없이 아래 엔딩과 최종값이 표시되는지 직접 확인한다. 숫자는 학업·체력·행복 순서다.

| 선택 순서 | 기대 결과 | 최종 능력치 | 확인할 경계 |
|---|---|---|---|
| `AAAA` | 목요일 재충전 필요 | 95 / 0 / 50 | 체력 20에서 CSV의 −25가 적용되면 실제 반영량은 −20 |
| `BABAABA` | 일요일 재충전 필요 | 100 / 0 / 50 | 일요일에도 0 판정 우선 |
| `ABABAAA` | 균형 달인 | 40 / 55 / 100 | 40 포함 |
| `AAABABA` | 아슬아슬 생존 | 85 / 15 / 85 | 한 능력치가 40 미만 |
| `AAABAAB` | 균형 달인 | 50 / 60 / 100 | 행복 95에서 CSV의 +15가 적용되면 실제 반영량은 +5 |

## 4. 390px 배치와 최종 확인

- [ ] 상단에 진행도와 능력치 막대·숫자가 먼저 보이도록 CSS를 작성한다. 요일, 사건과 버튼은 아래에 한 열로 배치한다. 긴 한국어 문구는 줄바꿈을 허용하고, 선택 버튼은 세로로 쌓는다. 선택과 결과 사이에서 상단 영역의 배치를 유지한다.
- [ ] 브라우저의 반응형 보기에서 뷰포트 폭을 390px로 설정한다. 시작, 선택, 결과, 엔딩과 다시 시작 흐름을 확인한다. 문구와 버튼이 잘리지 않고 가로 스크롤이 생기지 않으며 막대와 숫자가 0과 100에서도 읽혀야 한다.
- [ ] 브라우저에서 네트워크를 차단한 상태로 파일을 직접 다시 열어 월요일부터 엔딩과 다시 시작까지 진행한다. UTF-8로 저장되어 한글이 올바르게 보이고, 실행에 필요한 파일이 `index.html` 하나인지 확인한다.
